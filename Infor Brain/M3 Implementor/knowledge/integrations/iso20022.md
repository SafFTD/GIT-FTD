## ISO 20022 Overview

**Full name:** ISO 20022 Universal Financial Industry Message Scheme
**Authority:** ISO Technical Committee 68 (Financial Services)
**Classification:** INTEGRATION-GENERAL

ISO 20022 is a standard for financial messaging. It defines XML-based message schemas for payments, securities, trade finance, and other financial domains.

## pain.001.001.03 — Customer Credit Transfer Initiation

**Classification:** INTEGRATION-GENERAL

This is the standard ISO 20022 message used by a customer (debtor) to instruct their bank (debtor agent) to initiate credit transfers to one or more creditors (suppliers/payees).

This is the message type used in the HSBC H2H payment integration.

### Message structure (M3-GENERAL / INTEGRATION-GENERAL)

```xml
Document xmlns="urn:iso:std:iso:20022:tech:xsd:pain.001.001.03"
└── CstmrCdtTrfInitn  (Customer Credit Transfer Initiation)
    ├── GrpHdr         (Group Header) — 1..1
    │   ├── MsgId          Message ID — unique per message
    │   ├── CreDtTm        Creation date/time — ISO 8601
    │   ├── Authstn        Authorisation — optional
    │   ├── NbOfTxs        Number of transactions in this file
    │   ├── CtrlSum        Control sum (total amount)
    │   └── InitgPty       Initiating Party (who is sending)
    │       ├── Nm         Name
    │       └── Id/OrgId   Organisation identification
    └── PmtInf         (Payment Information) — 1..n — one per payment batch
        ├── PmtInfId       Payment information ID
        ├── PmtMtd         Payment method — TRF (Transfer)
        ├── BtchBookg      Batch booking indicator (true/false)
        ├── NbOfTxs        Number of transactions in this batch
        ├── CtrlSum        Control sum for this batch
        ├── PmtTpInf       Payment type information
        │   ├── InstrPrty  Instruction priority (NORM, HIGH)
        │   └── SvcLvl/Cd  Service level code
        ├── ReqdExctnDt    Requested execution date
        ├── Dbtr           Debtor (the paying company)
        │   ├── Nm
        │   └── PstlAdr    Postal address
        ├── DbtrAcct       Debtor account (company bank account)
        ├── DbtrAgt        Debtor agent (company's bank)
        │   └── FinInstnId/BIC
        ├── ChrgBr         Charge bearer (DEBT / SHAR / CRED)
        └── CdtTrfTxInf   (Credit Transfer Transaction) — 1..n
            ├── PmtId      Payment ID
            │   ├── InstrId     Instruction ID
            │   └── EndToEndId  End-to-end ID (unique reference)
            ├── Amt/InstdAmt Ccy="{CCY}"  Instructed amount with currency
            ├── CdtrAgt    Creditor agent (supplier's bank)
            │   └── FinInstnId (BIC + ClrSysMmbId + Nm + PstlAdr)
            ├── Cdtr       Creditor (supplier)
            │   ├── Nm
            │   └── PstlAdr
            ├── CdtrAcct   Creditor account (supplier's bank account)
            ├── Purp       Purpose code (optional)
            └── RmtInf     Remittance information
                └── Ustrd  Unstructured remittance text (invoice reference)
```

## Address Requirements in ISO 20022 (pain.001.001.03)

**Classification:** REGULATORY (ISO 20022 standard requirement — verify against standard documentation)

**OBSERVATION from HSBC project:** The data validation SQL requires `TOWN` (Town/City) and `CSCD` (Country) to be populated on supplier addresses. An `ISO20022_address_requirements.pdf` exists in the HSBC project but was not read during audit.

**Structured address elements observed in HSBC XML files:**

| XML Element | Meaning | Observed in HSBC | Notes |
|---|---|---|---|
| `StrtNm` | Street name | ✅ | Used in Dbtr and Cdtr addresses |
| `BldgNb` | Building number | ✅ | Used when address has building number |
| `PstCd` | Postal code | ✅ | Sometimes empty (`<PstCd/>`) |
| `TwnNm` | Town/City name | ✅ | **Required** (empty tag observed but data validation flags as invalid) |
| `CtrySubDvsn` | State/Province | ✅ | Used in MY addresses (e.g. "PG" for Penang) |
| `Ctry` | Country code | ✅ | ISO 3166-1 alpha-2 (e.g. MY, VN, SG, ID) |

> [!IMPORTANT]
> **OBSERVATION:** `<TwnNm/>` (empty town) was observed in some HSBC XML samples (VN file, SG file). The data validation SQL explicitly flags missing `TOWN` as `INVALID - Town/City Missing`. This confirms Town is required for this integration.
>
> **CLASSIFICATION:** Whether this is a universal ISO 20022 requirement or HSBC-specific is UNKNOWN pending reading of `ISO20022_address_requirements.pdf`.

## BIC / SWIFT Code (ISO 9362)

**Classification:** INTEGRATION-GENERAL (ISO 9362 is a public international standard)

### BIC format rules

- **Length:** 8 or 11 characters (never 9, 10, or other)
- **Structure:** `AAAA` (institution) + `BB` (country) + `CC` (location) + `DDD` (branch, optional)
- **Characters:** Positions 1–6: A–Z only; Positions 7–8: A–Z or 0–9; Positions 9–11: A–Z or 0–9
- **Case:** All uppercase
- **Branch code 'XXX':** Represents the primary office. The HSBC project SQL treats `XXX` as `INVALID - Dummy Branch Code (XXX)` — this is a PROJECT-SPECIFIC / BANK-SPECIFIC validation choice; whether XXX is universally invalid requires verification.

### BIC validation rules (from HSBC SQL — classified where possible)

| Rule | Classification | Detail |
|---|---|---|
| Length must be 8 or 11 | INTEGRATION-GENERAL | ISO 9362 requirement |
| All uppercase | INTEGRATION-GENERAL | ISO 9362 requirement |
| No spaces | INTEGRATION-GENERAL | Format requirement |
| Positions 1-6: A-Z only | INTEGRATION-GENERAL | ISO 9362 character rules |
| Positions 7-8: A-Z or 0-9 | INTEGRATION-GENERAL | ISO 9362 character rules |
| Branch positions 9-11: A-Z or 0-9 | INTEGRATION-GENERAL | ISO 9362 character rules |
| Branch code XXX invalid | BANK-SPECIFIC / PROJECT-SPECIFIC | HSBC project SQL rejects XXX — may not apply universally |

## Charge Bearer (ChrgBr) Codes

**Classification:** INTEGRATION-GENERAL (ISO 20022 standard codes)

| Code | Meaning |
|---|---|
| `DEBT` | All charges borne by debtor (paying company) |
| `SHAR` | Charges shared between debtor and creditor |
| `CRED` | All charges borne by creditor |

**HSBC project observation:** Both `DEBT` and `SHAR` are used across different payment scenarios. Which applies is BANK-SPECIFIC / COUNTRY-SPECIFIC.

## Country-Specific Format Notes

> Country-specific format variations are REGULATORY / BANK-SPECIFIC. Do not treat one country's requirements as applicable to others.

### Malaysia (MY)
- Payment types observed: DTN (Domestic Transfer Normal), HVP (High Value Payment), LVP (Low Value Payment)
- Currency: MYR
- Bank: HSBC Malaysia (BIC: HBMBMYKL)
- Local clearing system observed: `ClrSysMmbId/MmbId` included in creditor agent

### Vietnam (VN)
- Payment types observed: FTR (Foreign Transfer)
- Currency: VND (amounts in full units — e.g. 760,000,000 VND)
- Bank: HSBC Vietnam (BIC: HSBCVNVXXXX)
- Local clearing member ID used: `01310001` (VTCBVNVXXXX observed as creditor agent)
- `ChrgBr`: SHAR observed

### Singapore (SG)
- Payment types observed: FST (Foreign Swift Transfer)
- Currency: USD (cross-border)
- Bank: HSBC Singapore (BIC: HSBCSGSG)
- `Purp/Cd`: OTHR observed
- Service level: URNS

### Indonesia (ID)
- Payment types observed: FST
- Currency: IDR
- Bank: HSBC (specific BIC not confirmed from available files)
- Country-specific spec: `PP & ACH BI FAST XML V3-File Spec...Indonesia.docx` (not read — content unknown)

> [!WARNING]
> All country-specific entries above are PROJECT-SPECIFIC observations from the HSBC Gold Coin implementation. They should not be assumed to apply to other customers or banks in those countries.
